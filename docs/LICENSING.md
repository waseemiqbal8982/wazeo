# License / Access-Key System — Wazeo

## Overview
Wazeo sells access via **single-use license keys** (`WZ-XXXX-XXXX-XXXX`).
Licenses are generated by admins (optionally **unbound** — no email). A customer
redeems a key, binds their own email, verifies it via OTP, and gets access to a
plan (days or permanent) + features.

## Data model — `public.access_codes`
| Column | Meaning |
|---|---|
| `hash` / `code` | SHA-256 of the key secret (plaintext never stored) |
| `last4` | last 4 chars, for admin display/search |
| `email` | bound customer email (`null` = unbound) |
| `active`, `revoked`, `suspended` | lifecycle flags |
| `uses` (0/1), `used_at`, `used_by` | single-use consumption |
| `access_days` | `null` = permanent; else number of days |
| `plan_name`, `features`, `permissions`, `quota` | plan metadata |
| `expires_at` | key (redemption) expiry |
| `redemption_expires_at` | latest date the key can be redeemed |
| `bound_at`, `last_used_at`, `created_by`, `starting_balance` | audit |

## Backend routes
- `POST /api/auth/key-redeem`
  - `action=validate` — returns plan info + `bound_email` (no writes).
  - `action=bind` — **password-free email binding.** Atomically binds the email
    (`UPDATE … WHERE id AND email IS NULL AND uses=0 AND active AND NOT revoked
    AND NOT suspended`), creates/reuses the auth account (unconfirmed), applies
    the grant to `profiles`, consumes the license, sends OTP via `resend-code`,
    returns `needsVerify:true`.
  - `action=redeem` — legacy password path (kept for compatibility).
- `POST /api/admin/keys` (admin-only)
  - `generate` (single/bulk, `created_by` recorded), `revoke`, `regenerate`,
    `deleteExpired`, `setInvite`, `extendAccess`, `revokeUserAccess`.
  - License management: `suspend`, `reactivate`, `resetBinding` (full reset),
    `transfer` (rebind email), `adjustLicense` (days/plan/expiry/features/
    permissions/quota/starting balance). All audit-logged.

## Frontend
- `components/auth/AccessKeyRedeem.tsx`: key → validate → "Your key is valid!"
  animation → **bind email** (no password) → inline OTP → dashboard.
  - **`formatAccessKey` is the critical normalization** — strip the literal
    leading `WZ`, format the 12 body chars into 3×4, re-prepend `WZ-`. Do not
    reintroduce a bug that keeps `WZ` in the first body group.
- `components/admin/AdminKeys.tsx`: generates, lists (incl. Plan/Suspended),
  and manages licenses.

## Security notes
- Full secrets appear **once** at generation (admin) and are never re-served.
- Email binding is atomic on the server (single-claim), so two people cannot
  claim the same license.
- Access grant is stamped on `profiles` but only usable after OTP verification
  establishes a session.
- `createAdminClient()` **requires `SUPABASE_SERVICE_ROLE_KEY`** — it never
  falls back to the anon key (which is RLS-blocked for `access_codes` and would
  make every license appear invalid). If you see "This key is invalid, expired
  or not for this email", verify the service-role key is set in the deployed
  environment (Vercel) and redeploy. `/api/admin/config-status` reports this.

## Tests
- `npm run test:key` — pure validation/format logic (41 asserts).
- `npm run test:license` — live-DB workflow (`scripts/test-license-flow.mjs`):
  fresh unbound valid, atomic bind (email A wins, email B fails), used /

- `npm run lint` (0 errors), `npm run build` (pass).

## Remaining/manual
- OTP delivery requires working SMTP/Resend (see `docs/EMAIL_SETUP.md`).
- The legacy password `redeem` path is preserved; if you remove it, also update
  `components/auth/AccessKeyRedeem.tsx` (it now uses `bind` only).
